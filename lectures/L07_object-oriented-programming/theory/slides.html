Retrieval: One Sensor as a Dictionary

sensor = {
    "id": "T1",
    "unit": "C",
    "readings": [23.5, 24.0],
}

average = sum(sensor["readings"]) / len(sensor["readings"])

The dictionary stores state. The calculation supplies behavior elsewhere.

State or Behavior?

Classify each requirement:

  1. sensor identifier
  2. measurement unit
  3. stored readings
  4. add a reading
  5. calculate the average
  6. produce a readable report

State: identifier, unit, readings. Behavior: add, average, report.

Repeated Data Needs a Clear Home

With many sensors, separate dictionaries and functions create repeated coordination work:

sensor_1 = {"id": "T1", "unit": "C", "readings": []}
sensor_2 = {"id": "P1", "unit": "kPa", "readings": []}

add_reading(sensor_1, 23.5)
print(sensor_average(sensor_1))

A class defines one type whose objects keep related state and behavior together.

Part 1: Build the Mental Model

You Already Use Objects

name = "sensor-1"
values = [20.0, 22.0]

name.upper()          # method of a str object
values.append(24.0)  # method of a list object

Every Python value has a type and supports operations defined by that type.

type(name)    # str
type(values)  # list

A Class Defines a Type

class Sensor:
    pass
  • Sensor is the class name and the new type.
  • The indented block defines the type’s behavior.
  • class Sensor: uses modern Python 3 syntax.

The class is a definition—not one particular sensor.

An Instance Is One Particular Object

temperature = Sensor()
pressure = Sensor()

temperature and pressure refer to two distinct Sensor instances.

They share the structure defined by the class but can hold different state.

Class, Instance, Attribute, or Method?

class Sensor:
    def add_reading(self, value):
        self.readings.append(value)

t1 = Sensor()
t1.readings = []
t1.add_reading(23.5)

Identify Sensor, t1, readings, and add_reading.

Check: class, instance, data attribute, method.

A Class Is Useful When State and Behavior Belong Together

Use a class when:

  • many objects share the same structure;
  • operations depend on each object’s state;
  • a clear interface prevents repeated coordination code.

A standalone function is still better when no persistent object state is needed.

Part 2: Construct Independent Objects

__init__ Establishes Initial State

class Sensor:
    def __init__(self, sensor_id, unit):
        self.sensor_id = sensor_id
        self.unit = unit
        self.readings = []

Python creates a new instance and then calls __init__ to initialize it.

self refers to that newly created instance.

Constructor Arguments Become Attributes

t1 = Sensor("T1", "C")
p1 = Sensor("P1", "kPa")
name sensor_id unit readings
t1 "T1" "C" []
p1 "P1" "kPa" []

Do not supply an argument for self; Python supplies the new object automatically.

Trace One Construction

For:

t1 = Sensor("T1", "C")

Python calls the initializer conceptually as:

Sensor.__init__(new_sensor_object, "T1", "C")

Inside that call, self refers to new_sensor_object.

Predict Both Objects’ State

t1 = Sensor("T1", "C")
p1 = Sensor("P1", "kPa")

t1.readings.append(23.5)

What are t1.readings and p1.readings?

t1.readings is [23.5]; p1.readings remains []. Each initializer call created a separate list.

Instance State Must Be Stored on self

Local variables disappear

def __init__(self, sensor_id, unit):
    sensor_id = sensor_id
    unit = unit
    readings = []

Attributes remain with the object

def __init__(self, sensor_id, unit):
    self.sensor_id = sensor_id
    self.unit = unit
    self.readings = []

Use self.attribute for state that must survive after the method returns.

Avoid Shared Mutable State

Do not place a mutable collection where every instance will share it:

class Sensor:
    readings = []  # one list shared by the class

Create a new collection for each object:

def __init__(self, sensor_id, unit):
    self.readings = []

Repair the Initializer

class Sensor:
    readings = []

    def __init__(self, sensor_id):
        sensor_id = sensor_id

Make both sensor_id and readings independent instance attributes.

def __init__(self, sensor_id):
    self.sensor_id = sensor_id
    self.readings = []

Part 3: Give the Object Behavior

A Method Can Change Object State

class Sensor:
    def __init__(self, sensor_id, unit):
        self.sensor_id = sensor_id
        self.unit = unit
        self.readings = []

    def add_reading(self, value):
        self.readings.append(value)

add_reading changes the receiver object’s readings list.

Trace a Method Call

t1.add_reading(23.5)

This call is equivalent to:

Sensor.add_reading(t1, 23.5)
parameter value during the call
self the object referenced by t1
value 23.5

Which Object Becomes self?

t1.add_reading(20.0)
p1.add_reading(100.0)
t1.add_reading(22.0)

Predict the final readings stored in each object.

t1.readings is [20.0, 22.0]; p1.readings is [100.0].

A Query Method Returns Information

def reading_count(self):
    return len(self.readings)

def average(self):
    if not self.readings:
        raise ValueError("sensor has no readings")
    return sum(self.readings) / len(self.readings)

These methods observe existing state and return useful values.

The empty-data contract reuses Lecture 6 exception handling.

return and Mutation Serve Different Jobs

def add_reading(self, value):
    self.readings.append(value)  # changes state

def average(self):
    return sum(self.readings) / len(self.readings)  # reports state
  • A command-like method usually changes state.
  • A query-like method usually returns information.
  • Avoid printing inside reusable domain methods.

__str__ Supplies a Readable Interface

def __str__(self):
    return f"{self.sensor_id}: {len(self.readings)} readings ({self.unit})"
print(t1)
# T1: 2 readings (C)

__str__ must return a string. print displays that returned string.

Repair __str__

What is wrong with this implementation?

def __str__(self):
    print(self.sensor_id)

It prints but returns None. Replace the body with return self.sensor_id or a more informative string.

The Interface Hides Coordination Work

Client code can use the class without repeating its formulas:

t1 = Sensor("T1", "C")
t1.add_reading(20.0)
t1.add_reading(22.0)

print(t1)
print(t1.average())

The class owns the readings and the operations that depend on them.

Part 4: Complete and Verify the Class

A Complete Core Class

class Sensor:
    def __init__(self, sensor_id, unit):
        self.sensor_id = sensor_id
        self.unit = unit
        self.readings = []

    def add_reading(self, value):
        self.readings.append(value)

    def average(self):
        if not self.readings:
            raise ValueError("sensor has no readings")
        return sum(self.readings) / len(self.readings)

    def __str__(self):
        return f"{self.sensor_id}: {len(self.readings)} readings ({self.unit})"

Test Independent Instances

t1 = Sensor("T1", "C")
p1 = Sensor("P1", "kPa")

t1.add_reading(20.0)
t1.add_reading(22.0)
p1.add_reading(100.0)

assert t1.average() == 21.0
assert p1.average() == 100.0
assert t1.readings is not p1.readings

A second instance is an important regression test for accidental shared state.

Translate a Contract into a Class

A Resistor has a label and positive resistance. It calculates current for a supplied voltage and prints as R1: 220 ohm.

Identify:

  1. constructor parameters;
  2. instance attributes;
  3. ordinary method;
  4. special method;
  5. one invalid construction case.

Parameters and attributes: label, resistance; method: current(voltage); special method: __str__; reject resistance less than or equal to zero.

Optional Extension: Operator Methods

Python maps selected operations to special methods:

expression method
str(obj) obj.__str__()
a + b a.__add__(b)
a == b a.__eq__(b)

Only implement an operator when its meaning is natural and its contract is clear.

A Class Is a Tested Contract

  • The class defines a reusable type.
  • Each instance holds its own state.
  • __init__ establishes valid initial attributes.
  • self is the receiver object during a method call.
  • Methods either change state or return information.
  • __str__ returns a readable string.
  • Tests verify normal, boundary, invalid, and independent-instance behavior.
