Part 1: Protect the Data of an Object

Outside Code Can Skip the Check in __init__

r1 = Resistor("R1", 100)
r1.ohms = -50
print(r1.current(5))        # -0.1

r1.omhs = 220
print(r1.ohms)              # -50

__init__ checks the value one time, when the object is created

after that, Python accepts any value: a wrong result, and no error

a spelling mistake creates a new attribute; ohms does not change

We need a check that runs every time the value changes.

A Setter Method Checks Every New Value

class Resistor:
    def __init__(self, label, ohms):
        self.label = label
        self.set_ohms(ohms)

    def get_ohms(self):
        return self._ohms

    def set_ohms(self, value):
        if value <= 0:
            raise ValueError("ohms must be positive")
        self._ohms = value

setter checks the value, then stores it: r1.set_ohms(330)

getter returns the value: r1.get_ohms()

the constructor calls the setter, so the check is written once

the name _ohms starts with _. It means “internal: do not use outside the class”. Python does not block r1._ohms = -50; it is a rule for programmers.

@property Runs the Check for r1.ohms

class Resistor:
    def __init__(self, label, ohms):
        self.label = label
        self.ohms = ohms

    @property
    def ohms(self):
        return self._ohms

    @ohms.setter
    def ohms(self, value):
        if value <= 0:
            raise ValueError("ohms must be positive")
        self._ohms = value
>>> r1 = Resistor("R1", 100)
>>> r1.ohms
100
>>> r1.ohms = 330
>>> r1.ohms = -50
ValueError: ohms must be positive

@property this method runs when code reads r1.ohms

@ohms.setter this method runs when code writes r1.ohms = ...

the constructor writes self.ohms, so it runs the setter too

The code outside the class does not change: it still reads and writes r1.ohms.

A Property Without a Setter Is Read-Only

class Resistor:
    # __init__ and ohms: the same as before

    @property
    def conductance(self):
        return 1 / self._ohms

conductance is calculated from _ohms each time code reads it. The class stores only _ohms.

change ohms, and conductance changes too. The two values always agree.

there is no setter, so code cannot write to conductance: it is read-only

>>> r1 = Resistor("R1", 100)
>>> r1.conductance
0.01
>>> r1.ohms = 200
>>> r1.conductance
0.005
>>> r1.conductance = 2
AttributeError: property 'conductance' of 'Resistor' object has no setter

Part 2: Inheritance

A Subclass Is a Special Type of Its Parent Class

a parent class holds the data and methods that several types share

a subclass starts with everything its parent has. It can add methods and replace methods (this is called overriding).

a subclass can be a parent too: the chain can have many levels

test sentence: “a lamp is a device”. Write the shared code one time, in the parent.

The Parent Class: Device

class Device:
    def __init__(self, name, watts):
        self.name = name
        self.watts = watts
        self.is_on = False

    def switch_on(self):
        self.is_on = True

    def power(self):
        if self.is_on:
            return self.watts
        return 0

    def __str__(self):
        return f"{self.name}: {self.power()} W"

Nothing new here. Device is an ordinary class, as in Lecture 7.

three attributes: name, watts, is_on

command switch_on changes the state

query power returns the watts when the device is on, and 0 when it is off

__str__ calls self.power(). Remember this line: it matters later.

Lamp Inherits, Adds, and Replaces

class Lamp(Device):
    def lumens(self):
        return 90 * self.power()

    def __str__(self):
        return f"lamp {self.name}: {self.lumens()} lm"
>>> desk = Lamp("desk", 9)
>>> desk.switch_on()
>>> desk.lumens()
810
>>> print(desk)
lamp desk: 810 lm

Lamp(Device): the parent class goes in the parentheses

inherits Lamp has no __init__, so the Device constructor runs. switch_on and power also come from Device.

adds lumens is a new method. Only lamps have it.

replaces every Lamp uses this __str__, not the Device version

Python Looks in the Class of the Object First

desk.lumens(): Python finds lumens in Lamp. The search stops.

desk.switch_on(): it is not in Lamp, so Python looks in the parent and finds it in Device

print(desk): __str__ is in both classes. Python runs the first one it finds, in Lamp.

The search goes up only. A Device object never gets the methods of Lamp.

super() Calls a Method of the Parent Class

class DimmableLamp(Lamp):
    def __init__(self, name, watts, level=100):
        super().__init__(name, watts)
        self.level = level

    def power(self):
        return super().power() * self.level / 100
>>> hall = DimmableLamp("hall", 20, 50)
>>> hall.switch_on()
>>> hall.power()
10.0
>>> print(hall)
lamp hall: 900.0 lm

level=100 is a default value: the call can leave it out

super().__init__(name, watts) runs the parent constructor. It creates name, watts, and is_on.

then the subclass adds its own attribute: level, in percent

replaces power. super().power() gets the parent’s result first.

print(hall) runs Lamp.__str__ → self.lumens() → self.power(). Python finds the DimmableLamp version of power.

What Goes Wrong Without super().__init__()?

class DimmableLamp(Lamp):
    def __init__(self, name, watts, level=100):
        self.level = level

hall = DimmableLamp("hall", 20, 50)
print(hall.level)      # line A
print(hall.name)       # line B

Which line fails? Explain in one sentence.

Line A prints 50. Line B fails: AttributeError: 'DimmableLamp' object has no attribute 'name'. A subclass __init__ replaces the parent __init__. Python does not run the parent constructor for you, so name, watts, and is_on were never created.

One Loop Works for Every Type of Device

devices = [
    Device("router", 12),
    Lamp("desk", 9),
    DimmableLamp("hall", 20, 50),
]

total = 0
for device in devices:
    device.switch_on()
    print(device)
    total += device.power()
print(total, "W")

Output:

router: 12 W
lamp desk: 810 lm
lamp hall: 900.0 lm
31.0 W

a Device: Python runs Device.__str__ and Device.power

a Lamp: Python runs Lamp.__str__ and Device.power

a DimmableLamp: Python runs Lamp.__str__ and DimmableLamp.power

12 + 9 + 10.0 = 31.0 watts

The loop does not check the type. Each object runs its own version of the method. This is called polymorphism.

isinstance(desk, Device) is True: a Lamp is also a Device. isinstance(router, Lamp) is False.

Part 3: Class Variables, ==, and Composition

A Class Variable Is Shared by All Instances

class Board:
    next_serial = 1

    def __init__(self, model):
        self.model = model
        self.serial = Board.next_serial
        Board.next_serial += 1

    def tag(self):
        return f"{self.model}-{self.serial:03d}"
>>> a = Board("UNO")
>>> b = Board("UNO")
>>> a.tag(), b.tag()
('UNO-001', 'UNO-002')
>>> Board.next_serial
3

class variable next_serial is written under class, outside every method. There is one copy for the whole class.

a copies the number 1 into its own serial. Then the shared copy becomes 2.

b gets the number 2. Then the shared copy becomes 3.

read and change a class variable through the class name: Board.next_serial

__eq__ Defines What == Means for Your Class

>>> a = Coordinate(3, 4)
>>> b = Coordinate(3, 4)
>>> a == b
False

without __eq__, == asks “are these the same object?”. a and b are two objects.

__eq__ compares the data: the same x and the same y

with this method, a == b is True

class Coordinate:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

Composition: an Object Holds Other Objects

class Circuit:
    def __init__(self, volts, max_amps):
        self.volts = volts
        self.max_amps = max_amps
        self.devices = []

    def add(self, device):
        self.devices.append(device)

    def total_power(self):
        total = 0
        for device in self.devices:
            total += device.power()
        return total

    def is_overloaded(self):
        amps = self.total_power() / self.volts
        return amps > self.max_amps
>>> kitchen = Circuit(230, 10)
>>> kettle = Device("kettle", 2000)
>>> oven = Device("oven", 1500)
>>> kitchen.add(kettle)
>>> kitchen.add(oven)
>>> kettle.switch_on()
>>> kitchen.is_overloaded()
False
>>> oven.switch_on()
>>> kitchen.is_overloaded()
True

a Circuit has devices: the list is an attribute. A circuit is not a device.

total_power asks every device for its power. It works for every type of Device.

kettle on: 2000 W / 230 V = 8.7 A. This is below 10 A.

kettle and oven on: 3500 W / 230 V = 15.2 A. The circuit is overloaded.

Exit Ticket

Write the class Fan.

  • a Fan is a Device with one more attribute, speed (1, 2, or 3; the default is 1)
  • power() returns the Device power multiplied by speed / 3

class Fan(Device):
    def __init__(self, name, watts, speed=1):
        super().__init__(name, watts)
        self.speed = speed

    def power(self):
        return super().power() * self.speed / 3

Yes. Device.__str__ calls self.power(), and Python starts the search in the class of the object, Fan.

Summary

Protect the data

  • a setter checks every new value
  • @property keeps the object.attribute syntax
  • a property without a setter is read-only

Inheritance

  • a subclass inherits everything; it can add or replace methods
  • a subclass __init__ must call super().__init__(...)
  • Python looks in the class of the object first, then in the parents

Share and combine

  • a class variable has one copy, shared by all instances
  • “is a” means inheritance
  • “has a” means composition
