Retrieval: Parallel Lists

sensor_ids = ["S1", "S2", "S3"]
readings = [4.92, 5.31, 4.97]
statuses = ["normal", "high", "normal"]

To find the status of S2, which assumptions must remain true about all three lists?

The lists must have equal lengths and matching order. A dictionary can connect each sensor ID directly to its data.

Part 1: Dictionaries

A Dictionary Maps Keys to Values

List lookup by position

index value
0 4.92
1 5.31
2 4.97

Dictionary lookup by meaning

key value
S1 4.92
S2 5.31
S3 4.97

A dictionary is a mutable mapping: key → value.

Create a Dictionary

readings = {
    "S1": 4.92,
    "S2": 5.31,
    "S3": 4.97,
}

empty_registry = {}
  • A colon separates each key from its value.
  • Commas separate entries.
  • Curly braces create the dictionary.

Retrieve by Key

readings["S1"]       # 4.92
readings["S2"]       # 5.31
readings["S9"]       # KeyError: "S9" is absent

Direct indexing is appropriate when the key must exist. A missing required key often indicates a program or data error.

KeyError is a runtime exception. Part 3 shows how a program can respond to it.

Add, Update, and Delete

readings = {"S1": 4.92, "S2": 5.31}

readings["S3"] = 4.97          # new key: add
readings["S2"] = 5.08          # existing key: replace value

del readings["S3"]             # remove a required key
removed = readings.pop("S2")   # remove and return the value
fallback = readings.pop("S9", None)

After these lines: readings is {"S1": 4.92}, removed is 5.08, fallback is None.

What Does Membership Test?

readings = {"S1": 4.92, "S2": 5.08}

"S1" in readings             # True: tests keys
4.92 in readings             # False: not a key
4.92 in readings.values()    # True: explicitly tests values

Dictionary membership tests keys unless a values view is requested.

Keys Must Be Unique and Immutable

Common keys: strings, integers, and tuples of these (immutable values). Not valid as keys: lists and dictionaries (mutable values).

locations = {(2, 3): "sensor-A"}  # valid
# {[2, 3]: "sensor-A"}            # TypeError
registry = {"S1": 4.90, "S2": 5.08, "S1": 4.92}
print(registry)

{"S1": 4.92, "S2": 5.08}: a repeated key replaces its value.

Iterate Over Keys or Pairs

Keys (direct iteration)

for sensor_id in readings:
    print(sensor_id, readings[sensor_id])

Key–value pairs

for sensor_id, value in readings.items():
    print(sensor_id, value)
  • Direct iteration produces keys; readings.keys() is valid but unnecessary.
  • readings.values() gives only the values, e.g., for a total or average.
  • The pair from items() is unpacked into two loop variables, as with tuples in Lecture 4.

Count Events with a Dictionary

events = ["normal", "high", "normal", "low", "normal"]
counts = {}

for event in events:
    if event in counts:
        counts[event] += 1
    else:
        counts[event] = 1

print(counts)
{'normal': 3, 'high': 1, 'low': 1}

Each event is either a first occurrence or an update to an existing count.

Dictionary Trace Checkpoint

counts = {}
for code in ["A", "B", "A"]:
    if code in counts:
        counts[code] += 1
    else:
        counts[code] = 1

print(counts["A"], "C" in counts)

Check: 2 False. C never appeared, so it was never added as a key.

Choose the Data Structure

Choose list, tuple, or dictionary for each row.

# What we need to store Choice and reason
1 Voltages from one sensor, added as measured
e.g. 4.92, 5.08, 5.11, then 4.97 arrives		 list samples.append(4.97): the list grows, and the measurement order is kept
2 A sensor’s ID and its unit, which never change
e.g. S1 and V		 tuple ("S1", "V"): a small group of values that stays the same
3 The latest reading of each sensor, looked up by ID
e.g. S1 → 4.92, S2 → 5.08		 dictionary {"S1": 4.92, "S2": 5.08}: give the ID, get the reading

Part 2: Understand the Error

Retrieval: Text to Number

print(float("4.92"))
print(float("error"))

Before running the code, answer:

  1. What does line 1 print?
  2. What happens on line 2?
  3. Is the code wrong, or is the input text unsuitable?

Line 1 prints 4.92. Line 2 stops with ValueError: could not convert string to float: 'error'. The code is valid Python; the text "error" is not a number.

Three Kinds of Errors

Kind When Python finds it What you see
Syntax error Before the program runs SyntaxError; no line runs
Runtime error (exception) While a line runs A traceback and an error type
Logic error Never A wrong result and no message

Examples of the Three Kinds of Errors

Syntax

voltage = 5.4
if voltage > 5.0
    print("high")
SyntaxError: expected ':'

Runtime

limits = {"S1": 5.25}
print(limits["S9"])
KeyError: 'S9'

Logic

temps = [20.0, 22.0, 24.0]
avg = sum(temps) / (len(temps) - 1)
print(avg)
33.0

The correct average is 22.0.

sum(temps) adds all numbers in a list, like max() and min() from L04.

Classify the Errors

samples = [4.92, 5.08, 5.11]
limits = {"S1": 5.25, "S2": 5.25}

Write syntax, runtime, or logic for each line.

# Code or result Kind

3 fahrenheit = celsius * 9 / 5 - 32 gives 4.0 for 20 °C (expected 68.0) logic (should be + 32)

Read a Traceback from the Last Line Up

monitor.py

def to_number(text):
    return float(text)

records = [("S1", "4.92"), ("S2", "error")]

for sensor, text in records:
    value = to_number(text)
    print(sensor, value)
  1. Last line: the error type and the bad value ('error').
  2. Line above it: where it failed (line 2, inside to_number).
  3. Go up: who called that function (line 7).
S1 4.92
Traceback (most recent call last):
  File "monitor.py", line 7, in <module>
    value = to_number(text)
  File "monitor.py", line 2, in to_number
    return float(text)
ValueError: could not convert string to float: 'error'

Read This Traceback

summary.py

def average_reading(values):
    total = sum(values)
    return total / len(values)

print(average_reading([20.0, 22.0]))
print(average_reading([]))
21.0
Traceback (most recent call last):
  File "summary.py", line 6, in <module>
    print(average_reading([]))
          ~~~~~~~~~~~~~~~^^^^
  File "summary.py", line 3, in average_reading
    return total / len(values)
           ~~~~~~^~~~~~~~~~~~~
ZeroDivisionError: division by zero
  1. Which line fails, and in which function?
  2. Which call caused it?
  3. Which value is zero?

Check: line 3 in average_reading; the call on line 6, average_reading([]); len(values) is 0 because the list is empty.

Debug in Small Steps

Apply the five steps to the bug from the previous slide:

Step What it means For average_reading([])
1. Reproduce Run the failing input again average_reading([]) → ZeroDivisionError again
2. Reduce Find the smallest input that fails [] is already the smallest; [20.0] works
3. Locate Read the traceback; find the first wrong value line 3: len(values) is 0
4. Fix one thing Change one part of the code Decide: an empty list is not allowed (Part 3 shows how)
5. Retest Run every test again [20.0, 22.0, 24.0] → 22.0 · [20.0] → 20.0 · [] → a clear message

Change one thing, then run every test again.

Part 3: Handle Expected Errors

try and except Change the Order of Execution

text = "error"

try:
    value = float(text)
    print("Value:", value)
except ValueError:
    print("Not a number:", text)

print("Done")
  1. Python runs the try block line by line.
  2. float(text) raises ValueError, so the rest of the try block is skipped.
  3. The matching except block runs.
  4. The program continues after the whole statement.
Not a number: error
Done

Use try and except for errors you expect and can handle here.

Predict the Printed Letters

print("A")
try:
    print("B")
    value = int("4.5")
    print("C")
except ValueError:
    print("D")
print("E")

Write the printed letters in order.

Check: A, B, D, E. int("4.5") raises ValueError, so print("C") never runs.

Keep the try Block Small

limits = {"S1": 5.25, "S2": 5.25}
sensor, text = "S2", "error"

Too large

try:
    value = float(text)
    limit = limits[sensor]
    print(sensor, value > limit)
except ValueError:
    print("Not a number:", text)

Small

try:
    value = float(text)
except ValueError:
    print("Not a number:", text)

Put only the line that can raise the expected error inside try. Never write a bare except:; it also hides errors you did not expect.

Two Errors, Two Handlers

limits = {"S1": 5.25, "S2": 5.25, "S3": 5.00}
sensor, text = "S9", "5.10"

try:
    value = float(text)
    limit = limits[sensor]
    print(sensor, "alarm:", value > limit)
except ValueError:
    print("Not a number:", text)
except KeyError:
    print("Unknown sensor:", sensor)
Unknown sensor: S9

Python runs the first except whose error type matches.

What prints if sensor, text is:

  1. "S2", "error"
  2. "S3", "5.12"

Check: 1 Not a number: error; 2 S3 alarm: True.

Two Ways to Handle a Missing Key

limits = {"S1": 5.25, "S2": 5.25, "S3": 5.00}
sensor = "S9"

# 1. Check first
if sensor in limits:
    print("Limit:", limits[sensor])
else:
    print("No limit for", sensor)

# 2. Catch the error
try:
    print("Limit:", limits[sensor])
except KeyError:
    print("Unknown sensor:", sensor)
No limit for S9
Unknown sensor: S9
Way Use it when
1. Check first you can ask before you act
2. Catch the error a missing key means the task failed

raise: Report Input a Function Cannot Use

def average_reading(values):
    """Return the average of a non-empty list."""
    if len(values) == 0:
        raise ValueError("values must not be empty")
    return sum(values) / len(values)

try:
    print(average_reading([]))
except ValueError:
    print("No readings yet")
No readings yet
  • The function decides that an empty list is not allowed and raises ValueError with a clear message.
  • The caller decides what to tell the user.

Integration: Dictionaries Meet Exceptions

Sensor Status Report

limits = {"S1": 5.25, "S2": 5.25, "S3": 5.00}
records = [("S1", "4.92"), ("S2", "error"), ("S9", "5.10"),
           ("S3", "5.12"), ("S1", "5.40")]
counts = {}
for sensor, text in records:
    if sensor not in limits:
        status = "unknown"
    else:
        try:
            value = float(text)
            if value > limits[sensor]:
                status = "alarm"
            else:
                status = "normal"
        except ValueError:
            status = "malformed"
    if status in counts:
        counts[status] += 1
    else:
        counts[status] = 1
print(counts)
  • Unknown sensor: checked first (way 1).
  • Bad value: caught (way 2).
  • Lines 17–20: counting from Part 1.

 'unknown': 1, 'alarm': 2}

Summary

  • A dictionary maps keys to values. d[key] needs the key; check key in d first when it may be missing.
  • Three kinds of errors: syntax (before running), runtime (an exception while running), logic (a wrong result, no message).
  • Read a traceback from the last line up: the error type, the failing line, then the caller.
  • Debug in small steps: reproduce, reduce, locate, fix one thing, retest.
  • Put only the risky line in try and catch only the error you expect. Use raise when a function gets input it cannot use.
